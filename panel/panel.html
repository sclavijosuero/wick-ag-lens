  • Dynamic SPAs & State: The inspector automatically resyncs audits during client-side URL routing, dynamic DOM injections, and visibility attribute toggles (e.g., revealing a pre-rendered modal via CSS/ARIA). Rapid, continuous mutations are debounced (750ms) to preserve browser performance.
  • Visibility Filtering: Elements hidden via display: none, visibility: hidden, hidden, or inert are strictly excluded from all analysis to match native accessibility tree behavior.
  • Clipping & X-Ray Vision: Elements scrolled off-screen or hidden inside overflow: hidden containers (like carousels) are successfully detected and rendered with a ghosted X-Ray hatched pattern.
  • Z-Index Occlusion: Visibility calculations rely on CSS properties. The tool does not calculate 3D geometric occlusion (e.g., an element technically "visible" in the DOM but visually covered by a high z-index modal).
  • Focus Order: Mirrors standard browser Tab execution, prioritizing tabindex > 0, respecting native Radio Group bundling, and tracing hierarchical paths inside nested iframes.
  • Shadow DOMs: Standard (open) Web Components are fully traversed and supported. Explicitly 'closed' Shadow Roots remain inaccessible by browser design.
  • Iframes & Cross-Origin Policies: The tool successfully merges accessibility data across cross-origin iframes. However, it cannot bypass strict Same-Origin Policies to force scroll events inside cross-origin windows.
  • Color Contrast Heuristics: Contrast ratios are calculated using computed DOM styles. Elements overlaying complex backgrounds (images, gradients) are explicitly flagged for Manual Review.
  • WCAG Criteria Filtering: The version (2.0, 2.1, 2.2) and conformance level (A, AA, AAA) filters are strictly isolated. You must explicitly check all versions and levels you wish to evaluate in your current analysis.

  • Hardware & Monitor Limitations: All visual simulations are inherently constrained by the physical hardware of the screen. Absolute accuracy is limited by your monitor's specific color calibration, backlight brightness, viewing angle, and ambient room lighting.
  • Color Blindness (Viénot & Brettel Models): The color vision deficiency models rely on SVG feColorMatrix implementations. Protanopia and Deuteranopia use strict linearRGB Viénot physiological matrices, while Tritanopia utilizes an optimized linear least-squares approximation. Achromatopsia strictly follows the WCAG relative luminance formula rather than modeling biological rod-monochromacy.
  • Impaired Vision Approximations: Conditions like Cataracts and Loss of Contrast are generated using mathematical CSS filter combinations (blur, opacity, and amplitude reductions). They mimic the optical experience to identify severe contrast issues but do not perfectly replicate the physiological deterioration of the human eye.
  • Field Loss Topography: Central (Macular) and Peripheral (Glaucoma) visual field losses are simulated using CSS radial gradients bounded by static angles/percentages. These are 2D geometric approximations and do not account for physical biological blind-spot mapping, head movement, or dynamic pupil dilation.
  • Heuristic Scope: These tools provide an empathetic heuristic overlay to help developers identify critical contrast and layout barriers. They are strictly informational and cannot substitute for clinical diagnostic tools, native OS high-contrast modes, or actual user testing with assistive devices.
